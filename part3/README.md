part 3
Layihədə ilk olaraq tətbiqin daha modul və idarəolunan olması üçün Application Factory yanaşmasından istifadə etmək lazımdır. Bu məqsədlə create_app() funksiyası yaradılır və Flask tətbiqi birbaşa deyil, məhz bu funksiya vasitəsilə işə salınır. Beləliklə, development, testing və production kimi fərqli konfiqurasiyalar arasında rahat keçid etmək mümkün olur. Layihənin konfiqurasiya parametrlərini bir yerdə toplamaq üçün ayrıca config.py faylı yaradılır və təhlükəsizlik açarları, JWT parametrləri və verilənlər bazasının ünvanı burada saxlanılır. Bu, layihədə nizamlı və standartlaşdırılmış struktur təmin edir. Daha sonra istifadə olunacaq genişləndirmələr — bcrypt, JWT və SQLAlchemy — init_app() metodu ilə tətbiqə qoşulur ki, Application Factory ilə uyğun işləsin. API strukturu əsas tətbiqdən ayrılması üçün Blueprint yaradılır və register_blueprint() vasitəsilə tətbiqə əlavə edilir. Bu addım API kodunu daha səliqəli saxlayır və böyüdükcə idarə etməyi asanlaşdırır. Ümumilikdə, bu mərhələdə layihənin əsas karkası formalaşdırılır və sonrakı mərhələlərdə modellərin, repository qatının və biznes məntiqinin problemsiz şəkildə əlavə olunması üçün baza hazırlanır. Bu ardıcıllıq layihənin həm genişlənməsini, həm də test edilə bilməsini xeyli asanlaşdırır.
